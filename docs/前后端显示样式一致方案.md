# 前后端显示样式一致方案

## 1. 问题背景

同一份工程图模板,在前端编辑器 `cad-viewer-app`(SVG)里看到的,和后端
`src/dim_pdf_sheet.py` 直接生成的 PDF,视觉差异明显:

- 后端线条**过粗**,模型轮廓比标注引线粗数倍,像"截图放大";
- 后端标注线又**过细**,尺寸界线与箭头几乎看不清;
- 图纸幅面不一致(前端 A0 画布 1189×841,后端固定输出 A3),需额外映射。

根因是**样式参数两套硬编码**:前端写死在 `App.vue` 的 CSS 里(`stroke-width: 1`),
后端写死在 `dim_pdf_sheet.py` 的模块常量里(`_W_VISIBLE = 0.6`),两边各自调参、
互不知情,永远对不齐。

## 2. 统一坐标系:图纸坐标 = 毫米

前后端都改用**图纸毫米坐标**:

- 前端 SVG 的 `viewBox` 就是图纸幅面尺寸(选 A3 → `0 0 420 297`);
- 后端 PDF 页面尺寸直接取自模板 `sheet.width / sheet.height`,**不再做 A0→A3 映射转换**。

```js
// cad-viewer-app/src/composables/useCanvasTransform.js
export const SHEET_SIZES = {
  A0: { size: 'A0', width: 1189, height: 841 },
  A3: { size: 'A3', width: 420,  height: 297 },
  A4: { size: 'A4', width: 297,  height: 210 },
  ...
}
```

模板 JSON 记录真实幅面,后端原样取用:

```json
{ "sheet": { "size": "A3", "width": 420, "height": 297 } }
```

```python
# src/dim_pdf_sheet.py
sheet_w = template_doc["sheet"]["width"]    # 420
sheet_h = template_doc["sheet"]["height"]   # 297
c = pdf_canvas.Canvas(out_pdf, pagesize=(sheet_w * mm, sheet_h * mm))
```

`SheetMapper` 只做 **y 轴反转**(SVG y 向下 → PDF y 向上),不再缩放:

```python
class SheetMapper:
    def __init__(self, sheet_w, sheet_h):
        self.k = 1.0              # 图纸坐标即 mm,不再换算
        self.sheet_h = sheet_h

    def pt(self, x, y):
        return (x, self.sheet_h - y)
```

## 3. 统一度量衡:一律用 px,后端按 96dpi 折算 mm

线宽/字号在两端都不是"图纸比例量",而是**固定物理粗细**:

- 前端 SVG 的 `stroke-width` 配合 `vector-effect="non-scaling-stroke"`,
  无论图纸怎么缩放,屏幕上**恒为 1 设备像素**;
- 后端 PDF 是矢量,线宽是**物理毫米**,打印出来多粗就是多粗。

要让两者视觉等价,换算基准是 **96dpi**(浏览器 CSS 像素的标准分辨率):

```
1 px = 25.4 / 96 = 0.2645833 mm
1 px(字号) = 72 / 96 = 0.75 pt
```

所以配置里**统一用 px 表达**,后端读同一份配置后按上述系数折算成 mm / pt。

## 4. 共享配置:cad_viewer_style.json

配置放在**项目根** `cad_viewer_style.json`,前后端各自 import 同一份文件:

```
step__glb_pdf/
├── cad_viewer_style.json          ← 唯一真源
├── cad-viewer-app/src/composables/useStyleConfig.js   ← 前端读它
└── src/dim_pdf_sheet.py                                ← 后端读它
```

```json
{
  "edge": {
    "visible": { "stroke_px": 1.0, "color": "#303133" },
    "hidden":  { "stroke_px": 0.8, "color": "#999999" }
  },
  "dim": {
    "line":  { "stroke_px": 1.0, "color": "#303133" },
    "ext":   { "stroke_px": 0.8, "color": "#606266" },
    "text":  { "font_px": 9,     "color": "#303133" },
    "arrow": { "len_px": 3.5,    "half_px": 0.5 }
  },
  "center_mark": { "stroke_px": 0.8, "color": "#303133" },
  "_px_to_mm_at_96dpi": 0.2645833
}
```

### 前端接入

`useStyleConfig.js` 把 px 值注入 CSS 自定义属性,样式表不再写死数字:

```js
import config from '../../../cad_viewer_style.json'

export function useStyleConfig() {
  function applyToRoot(doc = document) {
    const root = doc.documentElement
    root.style.setProperty('--dim-line-stroke', config.dim.line.stroke_px)
    root.style.setProperty('--dim-ext-stroke', config.dim.ext.stroke_px)
    root.style.setProperty('--dim-text-size', `${config.dim.text.font_px}px`)
    root.style.setProperty('--edge-visible-stroke', config.edge.visible.stroke_px)
    ...
  }
  return { config, applyToRoot }
}
```

```css
.dim-line {
  stroke-width: var(--dim-line-stroke, 1);   /* 默认值兜底,未注入时仍可用 */
  vector-effect: non-scaling-stroke;
}
```

### 后端接入

```python
_STYLE_PATH = os.path.join(_ROOT, "cad_viewer_style.json")
with open(_STYLE_PATH, "r", encoding="utf-8") as f:
    _CFG = json.load(f)

_PX2MM = _CFG["_px_to_mm_at_96dpi"]           # 0.2645833
_W_VISIBLE = _CFG["edge"]["visible"]["stroke_px"] * _PX2MM   # 0.265 mm
_W_DIM     = _CFG["dim"]["line"]["stroke_px"]       * _PX2MM # 0.265 mm
_W_EXT     = _CFG["dim"]["ext"]["stroke_px"]        * _PX2MM # 0.212 mm
_FS_TEXT_PT = _CFG["dim"]["text"]["font_px"] * (72.0 / 96.0) # 9px → 6.75pt
```

## 5. 两端换算对照表

| 元素 | 配置(px) | 前端屏幕 | 后端(mm / pt) |
|---|---|---|---|
| 视图可见边线 | 1.0 | 1 设备像素(non-scaling) | 0.265 mm |
| 视图隐藏线 | 0.8 | 0.8 设备像素 | 0.212 mm(虚线) |
| 尺寸线 | 1.0 | 1 设备像素 | 0.265 mm |
| 尺寸界线 | 0.8 | 0.8 设备像素 | 0.212 mm |
| 中心标记 | 0.8 | 0.8 设备像素 | 0.212 mm |
| 标注文字 | 9 | 9px | 6.75 pt |
| 箭头长度 | 3.5 | 3.5 设备像素 | 0.93 mm |
| 图框 | 1.0 | 1 设备像素 | 0.265 mm |

## 6. 箭头特殊处理

箭头由前端 `dimensions/arrow.js` 生成,是**三个顶点的多边形**,尺寸写死在代码里:

```js
const ARROW_LEN = 14    // 画布像素
const ARROW_HALF = 1.6
```

这 14 是**图纸画布像素**(在 view bbox 内),不是屏幕像素。由于图纸坐标 = 毫米,
后端直接按图纸像素(=mm)渲染多边形,得到的箭头就是 14 mm —— 视觉上过大。

处理方式: 后端**不再二次缩放**,而是承认"图纸像素 = mm",把箭头缩到配置声明的
`arrow.len_px`(3.5 px → 0.93 mm)与前端屏幕视觉对齐。若模板由前端保存,
箭头几何已固化在标注的 `leaderLength` / 多边形顶点里,后端按同一 96dpi 系数解释。

## 7. 为什么不直接用 GB 工程图线宽标准

曾尝试按 GB/T 17453 给后端设"粗实线 0.6mm / 细线 0.25mm",结果:

- 后端 0.6 mm ≈ 2.27 屏幕像素,比前端 1 像素**粗 127%**,模型轮廓肉眼可见地压过标注;
- 工程图标准的层次感(粗实线 vs 细实线)是为了**纸质蓝图可读性**设计的,
  与"和前端屏幕所见一致"这个目标冲突。

结论: 本项目的目标是**前后端一致**(前端所见即后端所得),因此采用 96dpi 屏幕等效,
而非 GB 打印标准。若将来需要出蓝图,可在配置里单独加一套 `print_preset` 覆盖。

## 9. 调参方式

改 `cad_viewer_style.json` 一个文件即可同步两端:

- 觉得线太细 → 调大 `edge.visible.stroke_px` / `dim.line.stroke_px`;
- 觉得字太小 → 调大 `dim.text.font_px`(单位 px,后端自动 ×0.75 转 pt);
- 前端改完需**刷新页面**(`applyToRoot` 在 setup 时执行);
- 后端改完**直接生效**(每次渲染重新 `json.load`)。
