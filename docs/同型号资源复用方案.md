# 同型号资源复用方案

> 结论先行: 同一型号(完整 `model_code`,如 `250-E-H3K2-L100-D75B`)的产物一旦生成,
> 后续再选到该型号时直接取已有资源路径,不再重跑 OCC 装配。
> 命中时后端只回路径,前端跳过 `/api/build`;工程图源文件已存在则连服务端出图也省掉,
> 由网页端拿 `drawing_source.json` 回填规格。

## 1. 什么是"同型号"

`model_code` 全串一致即同型号,不是"同系列"。

- 同系列 = 前三段身份一致(`250-E-H2K1`),共用工程图模板,见 `docs/同系列模板复用规则.md`;
- 同型号 = 整串 `250-E-H3K2-L100-D75B` 一致,产物目录 `output/250-E-H3K2-L100-D75B/` 直接复用。

系列内换行程(`L100`→`L120`)或换电机(`D75B`→`D55B`)都是**不同型号**,产物各存一份、互不复用。

## 2. 产物与命中判定

产物落盘在 `output/<model_code>/`:

| 文件 | 来源 | 作用 |
|---|---|---|
| `assembly.glb` | `/api/build` | 小程序 3D 预览/下载 |
| `assembly.step`(`assembly.brep`) | `/api/build` | 工程图重绑的几何底 |
| `cylinder.step` | `/api/build` | 缸体单件 |
| `drawing_source.json` | `/api/render-drawing`(首次自动重绑) | 工程图源文件(视图/标注坐标) |
| `drawing.pdf` | `/api/render-drawing` | 回填规格后的成品 |

命中判定分两级:

- **3D 命中**:`assembly.glb` 与 `assembly.step` 都在 → 可跳过构建;
- **完整命中(`cached`)**:在 3D 命中的基础上,`drawing_source.json` 也在 → 连工程图重绑也省掉。

规格参数(手填值、备注、电机功率等)只影响标题栏与参数表文字,不改变视图几何,所以源文件可直接复用,`apply_spec` 原地回填即可。

## 3. 后端接口:GET /api/resources/&lt;model_code&gt;

只读,不触发任何构建。实现在 `src/web/blueprints/assembly.py` 的 `api_resources`。

请求:`GET /api/resources/250-E-H3K2-L120-D75B`

响应:

```json
{
  "ok": true,
  "model_code": "250-E-H3K2-L120-D75B",
  "cached": true,
  "model": {"available": true, "glb_file": "250-E-H3K2-L120-D75B/assembly.glb",
            "step_file": "250-E-H3K2-L120-D75B/assembly.step"},
  "cylinder": {"available": true, "file": "250-E-H3K2-L120-D75B/cylinder.step"},
  "drawing_source": {"available": true, "file": "250-E-H3K2-L120-D75B/drawing_source.json"},
  "drawing": {"available": true, "pdf_url": "250-E-H3K2-L120-D75B/drawing.pdf"}
}
```

| 字段 | 说明 |
|---|---|
| `model.available` | `assembly.glb` 与 `assembly.step` 同时存在 |
| `cached` | `model.available` 且 `drawing_source` 存在 |
| `glb_file` / `step_file` / `*.file` / `pdf_url` | 相对 `output/` 的路径,不存在时为 `null` |

返回的是相对 `output/` 的路径,**不是 http 地址**。前端统一用 `downloadUrl()` 拼成完整 URL,见第 4 节。

## 4. 前端接入

`newUp3/api/stepPdfResource.js` 增加封装:

```js
export const fetchModelResources = (modelCode) =>
	request(`/api/resources/${encodeURIComponent(modelCode)}`, 'GET', {}, false)
```

`newUp3/subPages/product/selectResult/selectResult.vue` 的 `generateStepResources()` 在构建前先查一次:

- 3D 命中 → `buildRes` 直接用 `resources.model.glb_file` / `step_file`,**不调 `buildUntilDone`**;
- 未命中 → 照旧 `buildUntilDone` 提交构建(此时后端仍按任务级去重);
- `drawing_source.json` 服务端或本地已存在 → 跳过服务端 `renderDrawing`,把源文件交给网页端(cad-viewer-app)按 spec 回填;
- 查询失败(接口不通)按未命中处理,回退原流程,功能不受影响。

拿到的相对路径一律经 `downloadUrl()` 转完整 URL,与构建流程完全一致:

```
250-E-H3K2-L120-D75B/assembly.glb
  → downloadUrl() → http://192.168.1.9:5001/download/250-E-H3K2-L120-D75B/assembly.glb
```

`downloadUrl` = `STEP_PDF_API_URL` + `/download/` + 逐段 `encodeURIComponent`;文件由后端 `/download/<filename>`(`send_from_directory(OUT_DIR, ...)`)提供。`STEP_PDF_API_URL` 见 `newUp3/config/env.js`(DEV `http://192.168.1.9:5001`,PRO `https://step.zg-yrj.com`)。

## 5. 与既有机制的关系

已有两条"复用",本方案补的是第三条:

| 机制 | 范围 | 现状 |
|---|---|---|
| `/api/build` 任务级并发去重 | 同型号任务**在跑**时复用同一 `task_id` | 已有;任务结束 key 释放,下次仍从头构建 |
| `/api/render-drawing` 源文件复用 | `drawing_source.json` 命中即回填出图,不重绑 | 已有 |
| 产物级缓存命中 | 产物已落盘即跳过构建 | 本次新增 `/api/resources` + 前端构建前查询 |

`/api/build` 本身未改:直接调 `/api/build` 仍会完整重算。缓存命中只在走小程序结果页时生效(先查资源再决定是否 build)。

## 6. 边界与注意

- 不做产物失效/版本:`output/<model_code>/` 一旦存在即视为有效。改了系列配置或电机零件后旧产物不会自动失效,需手动删掉该型号目录再重新生成。
- 命中只看文件名是否存在,不校验内容与生成时间。
- 前端本机缓存(`stepResCache_<modelId>`,localStorage)仍保留;换设备或清缓存后,靠本方案的服务端资源查询兜底。
- 微信小程序上线时,`downloadFile` 用到的域名须加入后台「downloadFile 合法域名」白名单;DEV 用局域网 IP 时手机需与电脑同网段。
