# 同系列工程图模板复用规则

> 结论先行: 型号 `250-E-H2K1-L100-D11` 中,前三段 `250-E-H2K1`(系列-连接类型-安装方式+负载连接)
> 决定整机结构,是**模板身份**;后两段行程 `L100` 与电机 `D11` 是**系列内变量**。
> 前三段相同的所有型号共用一份工程图模板,由后端按型号重算几何与标注值。

## 1. 型号编码规则

来源: `src/rebuild_assembly.py` 的 `parse_model_code()`。

```
250 - E - H2K1 - L100 - D11
 │    │    │      │      │
 │    │    │      │      └─ 电机编号(可选,D11/D55/D55B/D75/D75B)
 │    │    │      └─ 行程(L100 或 100,统一归一为 L100)
 │    │    └─ 安装方式(H*) + 负载连接(K*)
 │    └─ 连接类型(E=直连, F=折返, ...)
 └─ 系列(250)
```

电机编号映射(`MOTOR_CODES`):

| 编号 | 电机 |
|---|---|
| D11 | 11kw电机 |
| D55 | 5.5KW电机 |
| D55B | 5.5KW刹车电机 |
| D75 | 7.5kw电机 |
| D75B | 7.5kw电机刹车 |

连接类型决定系列配置目录: `E → data/configs/250直连.json`,其余 → `250折返.json` 等。
行程段允许省略 `L` 前缀(`100` 与 `L100` 等价);电机段可省略,省略时回退默认电机。

## 2. 同系列定义

**模板身份 = 前三段拼接**: `系列-连接类型-安装-负载`,如 `250-E-H2K1`。

以 `output/` 下已有型号为例:

| 型号 | 模板身份 | 行程 | 电机 |
|---|---|---|---|
| 250-E-H2K1-L100-D11 | 250-E-H2K1 | 100 | 11kw |
| 250-E-H2K1-L200-D55 | 250-E-H2K1 | 200 | 5.5KW |
| 250-E-H2K1-L100-D75B | 250-E-H2K1 | 100 | 7.5kw刹车 |
| 250-E-H2K4-L100-D75 | **250-E-H2K4**(不同模板) | 100 | 7.5kw |
| 250-E-H3K2-L100-D11 | **250-E-H3K2**(不同模板) | 100 | 11kw |

前三段相同意味着:

- 加载同一份系列配置 JSON(零件表、安装/负载/电机显隐规则、缸体参数);
- 安装方式与负载连接的显隐组合一致 → **可见零件集合一致**(仅电机件随电机编号切换);
- 装配体拓扑结构一致 → 各标准视图的边线**语义结构一致**,标注可以按几何特征重新对位。

## 3. 同系列内的不变量与变量

| 项 | 变化? | 规律 |
|---|---|---|
| 零件清单(除电机) | 不变 | 同一配置表,同一显隐结果 |
| 视图类型与布局 | 不变 | 模板定义 front/left/top 等视图及摆放 |
| 标注意图(标什么、标在哪) | 不变 | 模板承载;重绑后沿用 |
| 缸体长度 D1 | **随行程** | `D1 = stroke + C`(250直连 C=340,L100 → 440) |
| 缸体拉伸方式 | 随行程 | 沿主轴(Z)+Z 端单向延伸,-Z 端固定 |
| 配合零件位移 | 随行程 | 主轴安装坐标大于缸体安装位的零件同步平移 ΔD1 |
| 径向尺寸(缸径等) | 不变 | 拉伸只沿轴向,实测 L100/L200 的 X/Y 包围盒完全一致 |
| 电机/减速机几何 | **随电机编号** | 换用不同零件 BRep,包络不同(D11 减速机段 662mm,D75 618.5mm) |
| 标注数值 | 随上两项 | 由匹配到的边线 mm 坐标实时重算,模板不存数值 |

几何变化规律(实测 L100 vs L200,`250-E-H2K1` 系列):

```
           L100            L200
len_x       350   (不变)     350
len_y       303   (不变)     303
len_z      1632             1732   (+100 = Δstroke)
zmin    -798.74  (固定)  -798.74
zmax     833.26           933.26   (+Δstroke)
```

## 4. 模板复用机制(前端标注模板 → 后端批量出图)

### 4.1 模板来源

模板在前端 `cad-viewer-app` 编辑器里制作: 选一个**基准型号**(建议系列内最小行程 + 常用电机),
导入模型、放置视图、手工标注,保存为模板文件。模板即
`utils/drawingDocument.js buildDrawingDocument()` 的输出结构:

```json
{
  "sheet": {"size": "A0", "width": 1189, "height": 841},
  "model_id": "250-E-H2K1-L100-D11",
  "views": [{"id": "view_1", "source_view": "left", "x": 260, "y": 300, "scale": 0.32}],
  "annotations": [{"id": "dim_1", "type": "linear", "refs": [{"viewId": "view_1", "idx": 12, "type": "edges"}], "offset": 30}]
}
```

`model_id` 是基准型号,后端靠它还原模板制作时的边线语境。

### 4.2 核心问题: 边线引用必须重绑

前端标注的 `refs` 只记 `{viewId, idx, type}` —— 视图边线数组的**下标**。
换型号重新投影后,边线数量与顺序都会变(缸体拉伸边移位、电机件整体替换),
下标引用必然错位。所以模板复用的本质是**重绑(rebind)**:

1. 后端按 `model_id` 重新生成基准型号各视图 → 用 `idx` 还原每条标注引用的原始边线;
2. 生成目标型号各视图;
3. 对每条原始边线,在目标视图中按**几何指纹**寻找对应边线;
4. 匹配成功 → 用目标边线的 `meta.mm_coords` 重算标注值与位置;
   匹配失败 → 计入失配报告,**不做静默错位**。

### 4.3 几何指纹匹配规则

同系列模型的边线在结构上高度同源,匹配分两步补偿后再比对:

**位移补偿(行程差)**: 由锚点解析器(`src/anchor_resolver.py`)分别算出基准与目标
型号的缸体锚点,得到轴向位移量 Δ = D1_target − D1_base。视图轴向坐标大于缸体
安装位置的原始边线,比对前先平移 Δ;其余边线(电机侧、缸体后端)不动。

**指纹比对**:

| 特征 | 说明 |
|---|---|
| geom_type | line / circle / polyline,必须一致 |
| orientation | horizontal / vertical / angled,必须一致 |
| 位置 | 归一化中点坐标(相对视图包围盒),距离阈值匹配 |
| 长度/半径 | 相对包围盒尺寸的比例,容差比对 |

匹配在同(视图 × 类型 × 方向)分组内做,贪心取综合距离最小者,超过阈值判失配。

**电机区域的特殊性**: 换电机编号时电机/减速机边线整体替换,指纹匹配天然失配。
这类标注应在模板里声明为**文字型尺寸线**(`linear_text`,只标"减速机尺寸"不标数值),
两端绑电机包络锚点(`motor.axis_min_face` / `motor.axis_max_face`),锚点由
`anchor_resolver` 按当前型号电机零件 BRep 实测,自动跟随。

### 4.3 标注值重算

- 数值型: 取匹配后两条目标边线的 `meta.mm_coords`(模型真实 mm 坐标)重新计算
  距离/直径/角度,与前端 `dimensions/core.js` 的真值算法同源;
- 文字型: 文本原样保留,支持 `{{motor}}`、`{{model_code}}` 等占位符按目标型号参数替换;
- 位置: 视图布局沿用模板的 `x/y/scale`(比例可按目标包围盒微调,轴向延伸视图自动缩)。

### 4.4 失配处理

批量出图逐型号输出报告(`output/batch_report.json`):

- 每条标注给出 matched / unmatched + 失配原因(边线消失 / 电机替换 / 阈值超限);
- 失配标注在 PDF 上以醒目颜色绘出并注明"待修复",不参与数值渲染;
- 报告汇总后指导模板修订(通常是放宽阈值或改用锚点绑定)。

## 5. 两种模板形态

| | 规则式模板 | 实例式模板(前端标注) |
|---|---|---|
| 文件 | `src/drawing_template.json` | 前端导出的 DrawingDocument JSON |
| 制作方式 | 手写 JSON,标注以 `bbox_x_min` 等规则描述 | 编辑器里点选边线、所见即所得 |
| 绑定方式 | 规则匹配 + 语义锚点 | 几何指纹重绑 + 语义锚点 |
| 适用 | 通用骨架尺寸(总长/总宽/缸径) | 全量标注,含用户自定义尺寸线 |
| 出图 | `batch_drawing.py --template` | 计划: `batch_drawing.py --frontend-template` |

两者共用同一套出图管线(视图生成 → 锚点解析 → 标注求值 → PDF 渲染,
见 `src/batch_drawing.py`、`src/drawing_pdf.py`、`src/anchor_resolver.py`),
只是标注求值的绑定来源不同。
