# 电机减速机组合编号与选型方案

图库项目 23 个系列的电机表是电机选型的唯一数据源。当前编号生成把「同一功率配不同减速机」的多行覆盖成同一个 key，型号编码也没有减速机维度，导致前端选不到全部组合。本方案定义唯一编号规则、配置生成方式与前端选型界面的改造范围。

## 现状问题

`src/core/build_config.py:62-73` 的 `strip_code()` 取第一个括号前的内容作为电机 key：

```text
4.4kw电机(配115减速机) → 4.4kw电机
4.4kw电机(配142减速机) → 4.4kw电机
4.4kw电机(配160减速机) → 4.4kw电机
```

`build_motor()` 用 `cfg[code] = ...` 写入，同名互相覆盖，只写 warning。160直连 Excel 有 10 个有效组合，生成后的 `data/configs/160直连.json` 只剩 4 个 key，减速机维度丢失。

前端同样缺维度：

- `newUp3/api/motorPowerMap.js:56-62` 的 `buildMotorCode(power, brake)` 只按功率和刹车拼出 `D55` / `D75B`，不含减速机。
- `newUp3/subPages/product/selecte/selectionDefaults.js:100-130` 只有减速类型、减速比、是否适配，没有"115/142/160"这类机座型号字段。
- 后端 `/api/series/motor-table` 虽然下发了 `reducer`，但 `code` 仍然重复。

## 编号规则

格式：**`D<功率><B>_<减速机码>`**，功率保留小数点，减速机用下划线分隔。

| 段 | 规则 | 示例 |
|---|---|---|
| 功率 | 电机列解析出的 kW 数值，保留小数点 | `5.5`、`4.4`、`0.4`、`1.5`、`2.9`、`11`、`69` |
| 刹车 | 名称含"刹车"/"抱闸"或原编号以 B 结尾，加 `B` | `D5.5B` |
| 减速机 | `_` + 减速机列原文去掉"减速机"后缀；无减速机/单选时省略 | `_115`、`_142`、`_160`、`_AB182`、`_AB220`、`_60`、`_90` |

示例：

```text
D5.5           5.5kw 无减速机
D5.5_160       5.5kw 配160减速机
D4.4B_115      4.4kw 刹车 配115减速机
D7.5B_AB182    7.5kw 刹车 配AB182
D0.4_60        0.4kw 配60减速机
D1.5_115       汇川1500w 配115减速机
```

**刹车命名归一化**：Excel 里"刹车电机"与"电机刹车"是同一个东西，都指向同一批含"刹车"的零件（如 `汇川4.4kw刹车.SLDPRT`）。生成编号时统一按"名称含刹车/抱闸 → brake=true → 加 B"处理，不区分语序。

**为什么用下划线**：型号编码按 `-` 切段（`seriesMapping.js:34-40`、`rebuild_assembly.py:443`），下划线不冲突，motor 段能完整取到。小数点也是安全字符：`encodeURIComponent` 不转义 `.`，`output/<model_code>/` 目录名允许小数点。没有按 `.` 拆分型号的代码路径。

**不做旧配置迁移**：现有 `data/configs/*.json` 不修改、不补别名，后续全量重新生成覆盖。编号统一后，旧型号里的 `D55` / `D75B` 等段不再有效，用新编号 `D5.5` / `D7.5B` 代替。

前端必须传编号而非电机名称：`resolve_motor()` 的名称反查只认旧 `MOTOR_CODES`，传名称会报"本系列没有电机"；新编号不在 `MOTOR_CODES` 里时，`parse_model_code()` 原样返回 motor 段，`resolve_motor(config, motor)` 直接用它查配置，路径已通。

## 后端改造

**1. `build_config.py` 新增编号生成函数**

```python
def build_motor_code(name, reducer, power_kw, brake):
    """'5.5kw电机刹车(配160减速机)' + '160减速机' → 'D5.5B_160'"""
    power = format(power_kw, 'g')          # 5.5 / 4.4 / 0.4 / 11
    code = f"D{power}{'B' if brake else ''}"
    if reducer and '减速机' not in reducer and reducer != '无':
        code += f"_{reducer.strip()}"
    return code
```

`build_motor()` 的 `cfg[code] = {...}` 改用新 key；重名时按 reducer 区分后不再覆盖。`name` / `reducer` / `on` / `off` / `power_kw` / `brake` / `torque` 字段保持原样。

**2. 加刹车一致性校验**

生成时检查：名称含"刹车"但 `OnFeature` 里没有对应刹车零件（或反之）要报 warning。现已发现 `JDG135直连/电机.xlsx` 有一行 `4.4kw电机刹车(配斜齿160减速机）` 的 OnFeature 是 `汇川4.4kw<3>`（不带刹车），属于源数据错误，需先修正 Excel。

**3. 重新生成全部 23 个系列配置**

校验每个系列 `len(config.motor) == Excel 有效行数`，且无重复 code。160直连应为 10 个。

**4. `/api/series/motor-table` 不改结构**

`assembly.py:90-109` 已下发 `code / name / reducer / power_kw / brake / torque`，code 唯一后前端即可直接使用。

## 前端改造

把「功率下拉 + 抱闸开关」换成「电机组合单选」，选项来自 `/api/series/motor-table`。

| 文件 | 改动 |
|---|---|
| `selectionDefaults.js:154-195` | `motorPower` + `motorBrake` → `motorCombo`，一个下拉 |
| `motorPowerMap.js:56-62` | `buildMotorCode()` 不再自己拼，直接返回 combo 的 `code` |
| `backendConfig.js:192-243` | `applyMotorPowerOptions()` 消费完整电机条目，按 `name`（Excel 原文）显示 |
| `selection.js:102-105,343-347` | combo 变化时直接写 `selections.motor = combo.code` |
| `modelCode.js:28-58` | motor 段取 `selections.motor`，其余不动 |

**选项展示**：下拉文本直接用 Excel 电机列原文，如 `4.4kw电机(配115减速机)`、`5.5kw电机刹车(配160减速机)`。用户不需要理解编号规则，编号只在生成的型号编码里出现。

**不做三级联动**：功率→刹车→减速机三级联动需要额外维护合法组合表，而 Excel 每行本身就是一个合法组合（如 160直连只有 4.4kw 配 115，没有 5.5kw 配 115），直接列组合最简单且不会漏。

**联动清空**：改系列/结构时清空 `motorCombo`（`selection.js:349-360` 的 `clearDependentSelections()`），与现有 `motor` 字段一并处理。
