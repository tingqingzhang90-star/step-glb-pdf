# 关键接口说明

装配体生成与模板出图两条链路的调用方式、参数传递与并发行为。

服务基址:`http://127.0.0.1:5001`(见 `src/web/server.py`)。

## 一、通用约定

### 前端解包(容易踩)

`cad-viewer-app/src/utils/request.ts` 的响应拦截器**成功时只返回外层包装里的 `data`**,不是完整的 `{ok, data, ...}`。

```ts
// 后端返回 {ok: true, data: [...], total: 10}
const res = await getXxx(params) as any   // res 就是内层的 [...]
// 禁止写 if (res.ok) / res.data —— 数组没有这些字段,必然走空分支
```

后端返回**不带 `ok` 字段**的原始结构可绕过解包(如 `/api/files` 返回 `{groups, total}`)。

### 路径约定

| 用途 | 位置 |
|---|---|
| 装配产物 | `output/<model_code>/assembly.step`、`assembly.glb` |
| 构建元数据 | `output/<model_code>/build_info.json` |
| 出图 PDF | `output/<model_code>/drawing_frontend.pdf` |
| 模板文件 | `data/templates/engineering/<model_id>.json` |

接口返回给前端的是**相对路径**:构建结果相对 `output/`,出图结果相对**项目根**(即 `output/<型号>/drawing_frontend.pdf`)。两种基准不同,别混用。

### 型号编码与系列身份

型号形如 `250-E-H2K1-L100-D75`,**系列身份 = 前三段**,即 `250-E-H2K1`。同系列型号共用一份模板;跨系列几何差异过大,出图接口会直接拒绝。

## 二、装配体生成接口

### 1. GET /api/options

拉取全部系列的选型选项,用于渲染表单。

```json
{
  "series": [{
    "name": "250直连",
    "mount": ["E", "F"],
    "load": ["H2K1", "H2K4"],
    "motor": ["1", "2"],
    "strokes": ["L100", "L200"]
  }],
  "motor_codes": [{"code": "1", "name": "..."}]
}
```

数据来源:`data/configs/*.json` 每个文件一个系列。

### 2. POST /api/build — 提交构建

pythonOCC 非线程安全,构建放在**独立子进程**执行,由任务池调度,多用户互不阻塞。

请求体:

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model_code` | string | 是 | 型号编码,如 `250-E-H2K1-L100-D75` |
| `motor` | string | 否 | 电机编号,空串按 `None` 处理 |
| `series` | string | 否 | 系列名,为空时从型号推断 |
| `wait` | bool | 否 | `true` 时阻塞等待,直接返回结果 |
| `timeout` | number | 否 | 仅 `wait=true` 生效,默认 900 秒 |

**异步模式**(默认,不带 `wait`),HTTP 202:

```json
{"ok": true, "task_id": "build-0007", "dedup": false}
```

`dedup: true` 表示已有同型号任务在跑,复用了同一 `task_id`(同一型号并发构建会写同一个 `output` 目录,去重既省算力也避免产物写坏)。

**同步模式**(`wait: true`),HTTP 200:

```json
{"ok": true, "task_id": "build-0007", "result": {
  "step_file": "250-E-H2K1-L100-D75/assembly.step",
  "glb_file": "250-E-H2K1-L100-D75/assembly.glb",
  "cylinder_file": "..."
}}
```

失败:任务内异常 500(带 `traceback`),超时 504。

### 3. GET /api/task/&lt;task_id&gt; — 轮询进度

```json
{"ok": true, "task": {
  "task_id": "build-0007",
  "kind": "build",
  "key": "250-E-H2K1-L100-D75",
  "status": "running",
  "elapsed": 12.4,
  "log": ["[17:47:52] 任务启动 (pid=12345, kind=build)", "..."],
  "result": null
}}
```

- `status`:`pending`(排队)→ `running` → `done` / `error`
- `log`:子进程日志尾部,每个用户只看得到自己那条任务的进度
- `done` 且 `kind == "build"` 时,`result` 里的绝对路径已转成相对 `output/` 的下载路径

任务不存在返回 404。

### 4. GET /api/tasks — 任务池总览

```json
{"ok": true,
 "stats": {"workers": 12, "pending": 0, "running": 2, "done": 5, "error": 0, "total": 7},
 "tasks": [{"task_id": "build-0007", "kind": "build", "key": "...", "status": "running", "elapsed": 3.2}]}
```

多用户场景下可看到彼此的排队情况。`workers` 来自 `BUILD_POOL_WORKERS`,见 `.env.example`。

### 5. GET /api/files / GET /api/build-info/&lt;model_code&gt;

`/api/files` 列出 `output` 下已生成文件,按型号分组、最新在前:

```json
{"groups": [{"model": "250-E-H2K1-L100-D75", "has_info": true,
             "files": [{"name": "assembly.step", "rel": "250-E-H2K1-L100-D75/assembly.step",
                        "size": 12345, "mtime": 1788340000}]}],
 "total": 3}
```

`/api/build-info/<model_code>` 读 `build_info.json`,无记录 404。

### 6. GET /download/&lt;filename&gt;

按型号目录下载产物,`filename` 为型号目录下的文件名。

## 三、模板出图接口

完整链路:选模板 → 选同系列型号 → 批量生成 PDF → 下载/预览。

### 1. GET /api/drawing-templates — 模板列表

```json
{"ok": true, "templates": [{
  "template_id": "250-E-H2K1-L100-D11",
  "identity": "250-E-H2K1",
  "view_count": 1,
  "annotation_count": 8,
  "file": "250-E-H2K1-L100-D11.json"
}]}
```

### 2. POST /api/template-drawing/upload — 上传模板

两种提交方式任选:

- `multipart/form-data`,字段名 `file`(模板 .json 文件)
- `application/json`,请求体即模板文档

必填校验:`model_id`(非空字符串)、`views`(非空)。

落盘前服务端补全三个字段:`template_kind="frontend-instance"`、`template_identity`(由 `model_id` 前三段算)、`schema_version=1`。

```json
{"ok": true, "template_id": "250-E-H2K1-L100-D11", "identity": "250-E-H2K1",
 "view_count": 1, "annotation_count": 8}
```

### 3. GET /api/template-drawing/series-models — 同系列型号

查询参数:**`identity` 或 `template_id` 给其一**(`template_id` 会自动转身份)。

```json
{"ok": true, "identity": "250-E-H2K1",
 "models": [{"model_code": "250-E-H2K1-L100-D11", "has_pdf": false}]}
```

只返回 `output/` 下**存在 `assembly.step` 或 `assembly.brep`** 的型号——没有形状文件无法出图。

### 4. POST /api/template-drawing/generate — 批量出图

请求体:

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `template_id` | string | 是 | 已保存模板的 `model_id` |
| `models` | string[] | 是 | 型号编码数组,非空 |

响应:

```json
{"ok": true, "identity": "250-E-H2K1", "template_id": "250-E-H2K1-L100-D11",
 "results": [{
   "model_code": "250-E-H2K1-L100-D11",
   "ok": true,
   "pdf": "output/250-E-H2K1-L100-D11/drawing_frontend.pdf",
   "elapsed": 6.07,
   "dims": [{"id": "dim_1", "type": "linear", "mode": "single", "status": "matched", "reason": ""}],
   "unmatched": [],
   "error": null
 }]}
```

`dims[].status` 为 `matched` / `unmatched`;未匹配的标注会以红色文字写进 PDF,`unmatched` 里是 `"<标注id>: <原因>"`。

**参数传递链路**(这是出图慢与错位问题的关键):

```
template_id
  → 读 data/templates/engineering/<template_id>.json  得 template_doc
  → 系列校验:每个 model 的前三段必须等于模板 identity,否则 400 返回 rejected 列表
  → ① 基准任务 template-base(整批算一次)
        template_view_names(template_doc)     模板用到的视图集,通常 1~3 个
        resolve_base_views  → 基准型号的边线/隐藏边/bbox
        resolve_base_refs   → 每条标注引用的基准边线
        resolve_anchors     → 基准型号锚点档案
  → ② 每个型号一个 template-one 任务(并行)
        generate_one_frontend(model_code, template_doc, base.views, base.refs,
                              base.profile, out_dir, base.view_names)
        → 只投影模板视图集 → 标注重绑 → 渲染 PDF
```

两个约束不能破坏:

1. 基准与目标必须共用**同一个 `view_names`**。视图子集决定 `uniform_scale`,两边不一致会导致标注重绑整体错位。
2. `template-base` 整批只算一次并复用——若每个型号各算一遍基准,等于白跑一遍 HLR 投影。

### 5. GET /api/template-drawing/download/&lt;relpath&gt; / preview/&lt;relpath&gt;

`relpath` 即生成结果里的 `pdf`(相对项目根)。

- `download`:`Content-Disposition: attachment`,浏览器下载
- `preview`:`Content-Type: application/pdf` 内联,浏览器内嵌打开

两者都做目录穿越校验(规范化后必须仍在项目根内),文件不存在 404。

## 四、并发模型与去重

所有 OCC 计算都在 `src/web/task_pool.py` 的进程池子进程里跑,主进程不加载 pythonOCC。

| 任务类型 | 去重 key | 说明 |
|---|---|---|
| `build` | `<model_code>` | 同型号复用同一任务 |
| `drawing-views` / `-raw` / `-pdf` / `-dxf` | 各自 key | 单型号出图 |
| `view-palette` | `palette:<model_code>` | 视图调色板 |
| `view-single` | `palette:<model_code>:<view_name>` | 按需单视图 |
| `template-base` | `tpl-base:<template_id>` | 基准数据,同模板多用户共享 |
| `template-one` | `tpl:<template_id>:<model_code>` | 单型号出图,批次内并行 |

去重只在任务**未结束时**生效;结束后 key 释放,同 key 请求可重新排队。

并行度由 `.env` 的 `BUILD_POOL_WORKERS` 控制(默认 `min(4, CPU核数)`),详见 `.env.example`。任务在池内一律**串行投影**(`parallel=False`)——嵌套建池会让进程数按「任务数 × 视图数」爆炸,且每个子进程都要重新导入 pythonOCC。

批次内型号数 > worker 数时,多余的排队等待;多个用户的请求在同一池里公平交错。

## 五、错误码约定

| 状态码 | 场景 |
|---|---|
| 400 | 缺少必填参数、`models` 为空、跨系列(带 `rejected` 数组)、模板 JSON 非法 |
| 404 | 模板不存在、任务不存在或已清理、下载文件不存在 |
| 500 | 子进程任务失败(带 `traceback`)、模板读取/写入失败 |
| 504 | `wait=true` 时超时 |

前端侧:单型号失败不会中断整批,该条结果 `ok: false` 并带 `error`,其余型号照常返回。
