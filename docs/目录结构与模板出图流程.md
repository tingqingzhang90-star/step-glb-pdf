# 目录结构与模板出图流程

## 1. src 分层结构

原先 21 个模块平铺在 `src/` 根目录,按职责重新分层为四个包,
**依赖方向单向**: `web → batch → drawing → core`,禁止反向依赖。

```
src/
├── core/                        # 基础能力层(不依赖本包其他层)
│   ├── rebuild_assembly.py      #   装配体重建(型号解析/显隐/变换/STEP+GLB 导出)
│   ├── drawing_engine.py        #   pythonOCC HLRBRep 隐藏线消除 2D 投影引擎
│   ├── build_config.py          #   系列装配表 → data/configs/<系列>.json
│   ├── part_exporter.py         #   SW 装配体 → 系列零件库(参数化,CLI 与面板共用)
│   └── paths.py                 #   项目路径唯一真源
│
├── drawing/                     # 工程图领域
│   ├── anchor_resolver.py       #   按型号实时解析语义锚点(缸体端面/电机包络)
│   ├── frontend_template.py     #   前端实例模板装载与基准边线还原
│   ├── drawing_pdf.py           #   规则式管线的 reportlab PDF 渲染
│   ├── drawing_generator.py     #   早期 PyMuPDF + 参考 PDF 模板生成器(遗留)
│   ├── dxf_exporter.py          #   DXF 导出
│   ├── rule_template/           #   规则式模板引擎
│   │   ├── drawing_template.py  #     标注以 bbox_x_min 等规则描述
│   │   ├── drawing_template.json
│   │   └── drawing_anchors.json
│   └── dim/                     #   前端样式标注渲染链(与前端算法同源)
│       ├── dim_geometry.py      #     基础几何,移植自 dimensions/geometry.js
│       ├── dim_render.py        #     标注图元,移植自 dimensions/core.js
│       ├── dim_rebind.py        #     几何指纹重绑(基准边线 → 目标边线)

    │   ├── template.py          #   前端实例模板存取 + 模板出图
    │   ├── sw_view.py           #   SW 风格视图调色板
```

### 重命名说明

**文件名全部保持不变**,只加了包前缀。这样 import 改动最小、出错概率最低,
且原有文件名(`anchor_resolver`、`frontend_template`、`dim_rebind`)本身已足够清晰。

唯一的例外是规则式模板:为避免 `drawing.template.drawing_template` 这种
包名与模块名重复,该包命名为 `rule_template`。

### 重构注意事项(改动位置时必看)

移动文件会改变 `__file__`,以下几处**按 `__file__` 计算路径**,必须同步修正:

| 文件 | 路径常量 | 上溯层级 |
|---|---|---|
| `core/rebuild_assembly.py` | `_PROJECT_ROOT` | 3 级(core → src → 根) |
| `core/build_config.py` | `_PROJECT_ROOT` | 3 级 |
| `core/part_exporter.py` | `_PROJECT_ROOT` | 3 级 |
| `drawing/dim/dim_pdf_sheet.py` | `_PROJECT_ROOT`(读 `cad_viewer_style.json`) | 4 级 |
| `web/server.py` | `_HERE` / `_SRC_DIR` / `_PROJECT_ROOT` | 各自不同,见文件头 |
| `drawing/rule_template/drawing_template.py` | 同目录查找两个 JSON | 必须与 JSON 同目录 |

各入口脚本需把 **src**(而非自己所在目录)加入 `sys.path`:

```python
# src/batch/batch_drawing.py
_SRC_DIR = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
if _SRC_DIR not in sys.path:
    sys.path.insert(0, _SRC_DIR)
```

### multiprocessing 陷阱

`core/drawing_engine.py` 用 `ProcessPoolExecutor` 并行投影 9 个视图。
Windows 下是 **spawn** 模式:子进程会重新 import 主模块。

因此:

- **服务端安全**:`web/server.py` 的 `app.run()` 在 `if __name__ == "__main__"` 内,
  OCC 子进程不会重复启动 Flask 服务。
- **脚本必须加保护**:任何调用出图管线的脚本(`tools/_*.py`、测试脚本)
  都必须把执行体放进 `if __name__ == "__main__":`,否则子进程会递归
  重新执行主模块 → 无限 spawn → 卡死。
- 若子进程启动时主模块未受保护且内部有 HTTP 请求,会表现为"命令无响应"。

## 2. 模板出图流程(前端入口)

右侧属性面板「工程图状态」下有绿色按钮 **模板出图(批量生成 PDF)**,
打开 `TemplateDrawingPanel.vue` 三步向导。

### 三步向导

**第 1 步 · 选择模板** — 两个来源:

- 「从已保存模板选择」:列出 `data/templates/engineering/` 下全部模板
- 「导入模板文件」:拖入/选择前端导出的模板 JSON,上传即落盘

**第 2 步 · 选择型号** — 列出**同系列**且已生成过装配体的型号,默认全选。

同系列判定:型号编码前三段相同(见 `docs/同系列模板复用规则.md`),
例如 `250-E-H2K1-L100-D11` 与 `250-E-H2K1-L200-D55` 同属 `250-E-H2K1` 系列。

**第 3 步 · 生成下载** — 表格展示每张图的结果,可逐张「查看」(浏览器内嵌打开)
或「下载」。标注命中情况以标签展示:绿色=命中,红色=未匹配( hovering 看原因)。

### 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/template-drawing/upload` | 上传模板(multipart 或 JSON) |
| GET | `/api/template-drawing/series-models` | 列出同系列可出图型号 |
| POST | `/api/template-drawing/generate` | 批量出图 |
| GET | `/api/template-drawing/download/<rel>` | 下载 PDF(附件) |
| GET | `/api/template-drawing/preview/<rel>` | 预览 PDF(浏览器内嵌) |

### 安全与校验

- **下载路径防穿越**:`os.path.abspath` 规范化后必须仍在项目根内,否则 400
- **跨系列拒绝**:型号身份与模板身份不符时返回 400 并列出被拒型号,
  避免不同系列共用模板产生无意义图纸
- **模板完整性**:缺 `model_id` 或 `views` 为空时拒绝落盘

### 已知限制

- **同步阻塞**:出图为同步执行,每张约 5~15 秒(OCC 投影计算)。
  批量 N 张时前端会等待 N×10 秒左右,期间显示「正在生成」。
  Flask 以 `threaded=False` 运行,出图期间其他请求会排队。
  若后续需要更好的并发体验,可改为「提交任务 + task_id 轮询」的异步模式。
- **无中间进度**:逐张处理,前端只有最终的汇总结果。

## 3. 系列模板看板(`/series`)

按「配置(系列×连接) × 安装方式 × 负载方式」枚举模板身份(如 `160-F-H2K1`),
逐个显示基准模型是否已生成、该身份是否已有标注模板,可一键生成缺失的基准模型。

**指定身份采用的模板** — 同一身份下生成过多个模型时(不同行程/电机),
编辑器会按 `model_id` 分别落盘多份模板,它们的 `template_identity` 相同。
这时看板「模板」列会给出下拉框,从中指定一份作为**该身份生成工程图时统一使用**的模板;
不指定则沿用「标注最多」的自动挑选。

指定结果存在 `data/templates/identity_defaults.json`(`identity → template_id`),
与模板目录 `data/templates/engineering/` 同级另放,避免被模板扫描当成模板文件读进来。

取模板的唯一入口是 `template_helpers.find_template_by_identity`(顺序:人工指定 →
标注最多 → 无),因此指定对下面两条链路都生效:

- 小程序渲染 `/api/render-drawing` 缺 `drawing_source.json` 时的自动重绑;
- 看板自身的覆盖度统计。

指定的模板文件被删除后自动退回自动挑选,不会让出图卡死。
